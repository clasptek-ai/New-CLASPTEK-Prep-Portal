# ADR 027: Row Level Security (RLS) and Privileges Separation

## Context
Securing core examination details is critical. General students and anonymous users must not view draft, deprecated, or under-review versions. Administrative users need secure mutation capabilities.

## Decision
We enforce PostgreSQL Row Level Security (RLS) on all mutable tables:
- **SELECT Policies:** Allow anonymous/authenticated reads only if `status = 'PUBLISHED'` and `deleted_at IS NULL`.
- **WRITE Policies:** REST API endpoints authenticate tokens and restrict modifications to admin or service_role scopes.

## Consequences
- Multi-tenant security isolation at the database layer.
- Defense in depth: security is enforced even if application filters fail.
